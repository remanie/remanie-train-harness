What this repo does:
This audit covers the new RL harness and the Grok and Miles code it directly uses. Rust owns the coding conversation and eight native tools; Miles owns token records and training samples; trusted verifier code supplies the reward. The expected load is many isolated attempts, each with a single sequential model loop.

Cycle 2 audit, 2026-10-27. I read the final crate, assets, tests, adapter, documentation, dependency changes, and the connected native terminal, process-scope, tool-output, compaction and TLS code. The Miles review followed generation, failure collection, message matching, v2 trees, sample assembly, the wire codec, postprocessing and reward dispatch. I made no implementation changes. A separate fresh peer supplied cycle-2-peer-review.txt.

Must fix, found and resolved in this cycle:

1. An existing input reward bypassed the required verifier-result check. Source evidence: Miles' sample codec preserves a non-None input reward when the server reward is null, and generate_and_rm only invokes the reward hook for samples without a reward. A sample starting with reward=0 therefore skipped the hook even if its attempt failed. The fix at python/miles_grok.py:27-34 adds the small generate entry point and rejects pre-scored input before invoking Miles. The real Miles input/output and CLI contract is regression-tested. Without this guard, a stale score could enter training without successful verification.

2. Input metadata could forge a verifier result after an agent failure. Source evidence: agentic_tool_call.generate collects records even after child failure, and decode_samples_and_merge_input_sample overlays collected metadata on a copy of the original Sample. With agent metadata absent, an input metadata.rl_harness={"status":"graded","reward":99} survives and the adapter's reward hook returns 99. The fresh peer reproduced this through the actual generator, and this audit independently ran the real-codec reproduction. The fix at python/miles_grok.py:30-31 rejects any input rl_harness key before delegation. Null, empty and populated keys are tested. Without this guard, task input could impersonate the trusted adapter on an error path.

No unresolved finding remains in this scoped audit. The current behavior and its deployment boundaries are described below.

The registry contains exactly the agreed eight native tools. It has no subagent backend, skill collection, memory backend, production default toolset or model-visible approval tool. The code checks registered names before model requests and validates model arguments against the stored catalog before native dispatch. Unknown tools and fields become tool errors. Duplicate call IDs or malformed call structures reject a batch before any call in that batch changes the workspace. The agreed tool descriptions and argument wording are unchanged.

Each attempt exclusively creates its session directory and owns a terminal backend, todo state, process scope, HOME and TMPDIR. Snapshotting uses task metadata instead of copying process logs into compacted context. Todo state and running task IDs survive compaction and do not cross ToolSession instances. Native kill/wait semantics remain in use. Normal completion, deadline, error, signal cancellation and Drop close the attempt's native process groups. Both Rust and the built Python-to-Rust integration test verify actual PID cleanup.

The login-capture defect from cycle 1 is fixed in the native constructor. Only the explicit combination of disabled login capture and inherit=None skips the probe. Both spawn and WarmShell respect that initialized state, while default and absent policies keep their earlier behavior. The targeted native regression passed on macOS and Linux and tests six cases without executing the host's shell startup file. This is the only modified upstream runtime file outside the new crate.

The explicit child environment excludes caller API keys and verifier configuration. The native shell gets a fixed PATH and fresh attempt HOME/TMPDIR, with no inherited environment. The environment regression checks variable names only. Native grep now surfaces startup and regex failures instead of hiding stderr behind an empty formatted response; the original real-match assertion still passes. Debug builds need rg on PATH or an explicit native RG_BIN_PATH, as documented.

These measures do not create an OS sandbox. Native commands and absolute file paths can access the host environment. The external launcher must isolate files, processes, network and resources, keep grading authority and trainer credentials inaccessible to model-written code, and destroy the entire attempt environment. Rust shell tasks use separate process groups. If Rust crashes or receives SIGKILL, killing the Python-launched group alone is insufficient; outer sandbox teardown owns that case. No test here proves that deployment boundary.

The adapter receives trusted binary and verifier configuration outside the child payload. It passes only task text and runner settings to Rust, keeps other metadata for the verifier, and requires finite numeric rewards. A genuine verifier zero is valid. Runner failures and grader failures carry distinct error statuses and no fabricated reward. The required reward hook fails the rollout batch on an ungraded result. The new generate guard is part of the documented launch command and prevents both input-score bypasses above.

The verifier await has a separate deadline. Its callback must use asynchronous I/O; asyncio cannot interrupt synchronous blocking code or independently kill an external grading job. The README gives that boundary to the protected verifier service or environment owner. The adapter does not provision, reset or delete workspaces and does not allocate fresh paths for repeated dataset samples. The launcher must do that for each attempt. Reusing a session path is rejected before model calls.

The conversation loop preserves the original assistant JSON, including reasoning fields, null content and the original argument string. It does not reconstruct the assistant turn from parsed tool arguments. Real Miles strict-match and wire-codec checks retain the recorded token IDs and log probabilities. Compaction calls the same policy and session once, retains the original system prompt and task, then adds a cleaned summary and current tool metadata. It keeps the native executor alive.

The cycle-1 summary classification is fixed. Finished nonempty short summaries are accepted; malformed, tool-calling, empty and truncated policy summaries produce gradable invalid_response outcomes without replacing the old context. HTTP failures remain ungraded errors. The native production retry helper and its 500-character minimum have been removed from this path. The summary generation intentionally receives the attempt's reward once; copied summary text has zero loss as prompt context. The real Miles v2 CPU checks retain both roots and mask shared generated tokens once. They use synthetic records and do not establish a selected policy model's tokenizer or parser parity.

The compaction trigger includes endpoint usage, the serialized bytes of newly appended tool results, and a response reserve. It is an estimate, not an exact tokenizer. The caller must leave model-context headroom. A server overflow is an error, with no silent context truncation or retry. Requests and responses are capped at 16 MiB, process logs at 16 MiB, and the execution journal at 256 MiB. The 512-policy-turn bound fits the Miles 1024-node limit even with an intervening summary each turn. External quotas still control total disk, CPU, memory and process use across concurrent attempts; no throughput benchmark was run.

The dependency change adds the new crate and its package entry without upgrading upstream packages. Reusing native tools retains the existing dependency graph. Extracting it would be separate work and is not required to run this implementation. The final HTTP client uses the repository's TLS helper, whose connected source was read; it preserves the request timeout and no-redirect policy and introduces no application credentials or model instructions. Original license and third-party notices remain present.

Verdict: Ship within the documented isolated-attempt runner and Miles integration scope. Both review cycles found concrete bugs, and their fixes have executable regression evidence. This verdict does not certify a production training environment or model-learning result.
